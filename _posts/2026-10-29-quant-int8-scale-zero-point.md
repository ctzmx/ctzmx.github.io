[《深度学习数据精度（一）》]({% post_url 2026-10-28-deep-learning-numerical-precision-basics %})从位分配出发，介绍了 FP32、BF16、FP16、FP8 和整数格式。文章在 INT8 那一节留下了一个问题：**整数只有 -128 到 127，怎样用它表示模型里大量的小数？**

答案藏在当时给出的公式里：`x_hat = scale × (q - zero_point)`。整数编码本身没有小数部分，但配合缩放因子和零点，就能对应到一组离散的实数。量化要决定的，是怎样用这组有限的值近似原来的张量，并让误差与部署成本都可以接受。

这一篇作为[量化 Quant 栏目]({{ '/quant/' | relative_url }})的起点，先讲最基础的**均匀仿射整数量化**，再把它放回模型推理的上下文。[《深度学习数据精度（二）》]({% post_url 2026-10-28-deep-learning-floating-point-errors %})讨论过的舍入、存储和累加格式，会在这里继续用到；FP8、FP4 的缩放方案以及具体 LLM 量化算法留待后续展开。

## 1. 从数值格式到量化方案

在相同数量级内，浮点数的小数位越少，相邻可表示值的间隔通常越大。把 FP32 转成 FP16，就是把原来的数舍入到 FP16 所定义的数值集合上，转换还可能受到表示范围的限制。

整数量化也要把数映射到有限的集合，只是这里还需要为张量选择一套映射参数。例如，同一个整数编码 `q = 10`，在 `scale = 0.1`、`zero_point = 0` 时表示 1.0；在 `scale = 0.01` 时则表示 0.1。

因此，“使用 INT8”只交代了一部分信息，还要继续问：哪些张量被量化，整数对应什么实数，哪些元素共用参数，以及实际计算和累加使用什么格式。

本文的“均匀”指：**在共用同一组参数的元素中，相邻整数对应的实数间隔相同。** 它和浮点格式随数量级改变间隔的方式不同。量化还可以使用浮点格式或非均匀的数值集合，所以不能把本文的整数公式当成所有量化方案的完整定义。

## 2. scale 与 zero_point：整数怎样表示小数？

对一个有限实数 `x`，常见的仿射量化与反量化可以写成：

```text
量化：   q = clip(round(x / scale) + zero_point, qmin, qmax)
反量化： x_hat = scale × (q - zero_point)
```

其中：

- `scale > 0` 是缩放因子，也是在这组参数下，相邻反量化值之间的间距。
- `zero_point` 是实数零对应的整数编码，需要是 `[qmin, qmax]` 内的整数。
- `round` 把缩放后的值舍入到整数；本文采用“舍入到最近值，平局取偶数”。
- `clip` 把超出范围的编码限制到端点，也称裁剪或饱和。
- `x_hat` 是重构的近似值。反量化不能找回舍入和裁剪时丢失的信息。

这里的裁剪不是“向零截断取整”。例如，2.8 舍入到最近整数得到 3；若允许的最大编码只有 2，随后才会被裁剪成 2。

沿用精度（一）里的例子，完整 INT8 编码范围为 `[-128, 127]`，设 `scale = 0.02`、`zero_point = 0`：

```text
x = 0.18
q = round(0.18 / 0.02) = 9
x_hat = 0.02 × 9 = 0.18

整数编码：  -128, -127, …, 0, …, 126, 127
对应实数： -2.56, -2.54, …, 0, …, 2.52, 2.54
```

在数学上的映射关系中，0.18 恰好落在这个网格上；实际用二进制浮点数保存 0.02、0.18 和执行运算时，还可能带来很小的浮点误差。

更一般地，解码网格的两个端点是：

```text
x_min = scale × (qmin - zero_point)
x_max = scale × (qmax - zero_point)
```

端点之间仍只有离散的可表示值，并不包含其中所有实数。`scale` 决定间距，`zero_point` 决定零在整数编码中的位置。

## 3. 对称与非对称：为什么需要零点？

### 3.1 对称量化：先围绕零建立网格

对于正负值都较多的权重，一个常见起点是令 `zero_point = 0`。为让两侧端点严格对称，本文后面的 INT8 实验只使用 `[-127, 127]`，有意不用 `-128`。

若选择的实数边界是 `[-A, A]`，且 `A > 0`，这套约定对应：

```text
scale = A / 127
zero_point = 0
```

这是一种常见约定，不能据此认定所有 INT8 实现都舍弃 `-128`。读取模型或框架配置时，需要确认实际编码范围。若张量全为零，也不能直接得到 `scale = 0`；实现应选择正的 scale，使这些零仍编码为零点。

### 3.2 非对称量化：把编码分配给不对称的范围

如果数据范围明显偏向一侧，可以移动零在编码中的位置，让可用编码覆盖更合适的范围。例如使用 UINT8 的 `[0, 255]`，设置：

```text
scale = 0.02
zero_point = 50

q =   0 → x_hat = -1.00
q =  50 → x_hat =  0.00
q =  80 → x_hat =  0.60
q = 255 → x_hat =  4.10
```

这个网格仍然等间隔，但实数范围偏向正数。这里的 `zero_point = 50` 表示“实数零用编码 50 保存”，并不表示数据最小值是 50，也不是把模型里的零改成 50。

实际方案通常根据选定范围计算参数。零点需要取整数，因此最终解码端点未必恰好等于最初设想的范围。对称或非对称的选择还受算子和硬件支持影响，不能只凭数据分布决定。

## 4. 一个 INT8 小实验：舍入误差与裁剪误差

下面选 `scale = 0.125`、`zero_point = 0`，使用对称编码 `[-127, 127]`，所以解码端点为 `[-15.875, 15.875]`。这些数字和输入都可以用二进制精确表示，便于单独观察量化映射。

本文代码已在 Windows x64、Python 3.12.14、NumPy 2.3.5 的 CPU 环境运行。实验用 FP64 计算中间值，整数编码实际存成 `np.int8`；它用于说明量化与反量化中的数值变化，不代表 INT8 推理内核，也不测量加速效果。

```python
import numpy as np

x = np.array(
    [-20, -0.3125, -0.0625, 0, 0.0625, 0.3125, 20],
    dtype=np.float64,
)
scale = 0.125
zero_point = 0
qmin, qmax = -127, 127

# 先舍入和裁剪，再转成 INT8，避免越界类型转换改变编码。
rounded = np.rint(x / scale) + zero_point
q = np.clip(rounded, qmin, qmax).astype(np.int8)

# 先扩展类型再减零点，避免在窄整数类型里进行减法。
x_hat = scale * (q.astype(np.float64) - zero_point)
error = np.abs(x_hat - x)

print("       x     q    x_hat  abs_error")
for value, code, restored, err in zip(x, q, x_hat, error):
    print(f"{value:8.4f} {int(code):5d} {restored:8.4f} {err:10.4f}")
```

运行结果：

```text
       x     q    x_hat  abs_error
-20.0000  -127 -15.8750     4.1250
 -0.3125    -2  -0.2500     0.0625
 -0.0625     0   0.0000     0.0625
  0.0000     0   0.0000     0.0000
  0.0625     0   0.0000     0.0625
  0.3125     2   0.2500     0.0625
 20.0000   127  15.8750     4.1250
```

### 4.1 范围内：舍入到最近的网格点

`0.3125 / 0.125 = 2.5`，平局取偶数得到编码 2，再反量化为 0.25。`0.0625 / 0.125 = 0.5`，平局取偶数得到编码 0，因此这个非零输入被映射成了零。

对于落在解码端点之间的输入，在理想的缩放计算和最近值舍入下，一次量化的绝对误差满足：

```text
abs(x_hat - x) <= scale / 2
```

本例上界是 0.0625。这个结论只描述一次映射，不能直接作为整个模型输出误差的上界；实际计算还可能叠加浮点运算误差。

靠近零的数被舍入成零，是这里的整数网格太粗，不需要用 IEEE 浮点“下溢异常”来解释。两种机制都可能丢失小数值，但具体规则不同。

### 4.2 范围外：饱和并不会生成 Inf

20 缩放后得到 160，超过编码上限 127，因此被裁剪成 127，反量化后只有 15.875，绝对误差为 4.125。负方向同理。

这里输出仍然有限，却已经明显偏离输入。精度（二）里用有限性检查定位 `Inf/NaN` 很有用，但量化中的饱和通常不会产生这些特殊值，因而还要检查裁剪比例和重构误差。

超出解码端点的输入不再享有前面的 `scale / 2` 误差界。继续把 scale 调小，会细化网格，同时让更多输入落到范围之外。

*图 2：上图放大范围内的舍入，下图展示端点处的饱和，两幅数轴采用不同的观察范围。箭头终点都是反量化后的近似值；裁剪后结果仍然有限。*

## 5. 范围、校准与粒度：scale 应该怎样选？

### 5.1 范围越宽，同样位数下间隔越大

仍以对称 INT8 为例，最直接的选择是取张量最大绝对值作为 `A`，令 `scale = A / 127`。这能覆盖当前观察到的数值，但不一定最有利于保留主要部分的信息。

假设绝大多数元素位于 `[-1, 1]`，少数离群值达到 32：

| 选定边界 A | scale | 取舍 |
| --- | --- | --- |
| 32 | `32 / 127 ≈ 0.2520` | 可以覆盖 32，但小数值之间的差别可能被合并 |
| 1 | `1 / 127 ≈ 0.007874` | 主要区间的网格细 32 倍，但 32 会被裁剪到 1 |

这张表展示了一个取舍：扩大范围会增大舍入误差的潜在上界，缩小范围会增加裁剪风险。**离群值少，并不说明它们对模型不重要。** 不能因为多数元素的重构更精细，就断言第二种选择的模型效果更好。

[![在相同的负 1 到 1 局部窗口内，边界 A 为 1 的 INT8 网格比 A 为 32 的网格细 32 倍，但输入 32 会被前者裁剪到 1](/img/posts/quant-int8/range-resolution.svg)](/img/posts/quant-int8/range-resolution.svg)

*图 3：两行使用相同的局部实数轴。扩大覆盖范围后，有限的编码要分配到更长的区间，因此主要数据区间里的格点变少。选择较细的网格，同时意味着接受窗口外大值被裁剪的风险。*

### 5.2 校准：用代表性数据观察真实数值范围

权重在模型确定后就可以直接读取；激活则依赖输入。静态激活量化通常会先让模型处理一批代表性样本，收集激活统计，再决定部署时使用的范围与参数，这个过程称为校准。

MinMax、百分位或以重构误差为目标的方法，会以不同方式处理范围和离群值。校准得到的参数只反映观察到的数据，不能保证未来输入始终落在其中。对 LLM，校准数据的语言、任务、长度和输入模板应尽量覆盖目标使用场景；评估效果时还需要独立的测试数据。

动态激活量化则在运行时根据当前输入计算相应参数，能适应输入变化，同时带来统计和转换开销。“静态/动态”主要描述参数何时确定，不等于量化位数或模型效果的高低。

### 5.3 粒度：哪些元素共用一套参数？

如果两个通道的数值范围相差很大，让它们共用一个 scale，可能迫使小范围通道使用过粗的网格。于是量化参数也有不同的共享粒度：

| 粒度 | 参数如何共享 | 主要考虑 |
| --- | --- | --- |
| per-tensor | 整个张量共用一组参数 | 参数开销小，容易受到局部大值影响 |
| per-channel / per-axis | 沿指定轴分别使用参数，例如每个输出通道一组 | 能适应通道间差异，要确认轴的定义和算子支持 |
| per-group / per-block | 按指定方式分组，每组元素共用参数 | 可以适应更局部的范围，需要记录组大小、方向和布局 |

LLM 权重量化里常见的 `group_size`，就在描述分组方案的一部分；同一个数字并不能完整说明如何分组。粒度变细通常增加 scale 等元数据，并影响内核实现和数据搬运，不能只根据组数判断实际效果或速度。

[![一个 4 行 8 列权重矩阵的参数共享方式：per-tensor 共用一组，按行的 per-channel 使用四组，沿行每四个元素一组的 per-group 使用八组](/img/posts/quant-int8/parameter-granularity.svg)](/img/posts/quant-int8/parameter-granularity.svg)

*图 4：同色区域共用一组量化参数。本例把行视为输出通道，分组沿每行进行；颜色表示共享关系，不表示数值大小或误差。具体模型的轴与分组方式仍需查配置。*

## 6. PTQ 与 QAT：什么时候让模型适应量化？

建立了映射后，还需要决定如何把它用于已经训练好的模型或训练过程。

| 路径 | 基本做法 | 需要理解的边界 |
| --- | --- | --- |
| PTQ，训练后量化 | 从已训练模型出发，选择量化参数并转换模型 | 通常不需要完整重训；具体方法仍可能包含校准、参数优化或局部重构 |
| QAT，量化感知训练 | 在训练或微调时引入量化影响，让参数适应这种误差 | 常见做法是用浮点张量模拟量化与反量化，训练结束后再转换成部署形式 |

QAT 不意味着训练的每一步都使用 INT8。常见的伪量化会模拟舍入和裁剪，但仍保留浮点参数与梯度，并用近似方式处理不可直接求导的舍入操作。

PTQ/QAT 讨论的是模型如何准备或适应量化；静态/动态讨论的是相关参数何时确定，per-tensor/per-channel 讨论的则是参数共享方式。它们回答的是不同问题，读方案时需要分别确认。

这一篇先停留在这些概念。后续理解 GPTQ、AWQ 等方法时，再看它们针对哪类误差、利用了哪些统计，以及如何选择或调整量化方案，会更容易把细节放到正确的位置。

## 7. INT8 权重，不等于整条路径都用 INT8

精度（二）强调过，要分开看存储、计算、累加和输出。量化也一样：

- `W8A8` 通常表示权重与激活采用 8 位，但还要确认是整数还是某种浮点格式、哪些算子被覆盖，以及累加格式。
- `W4A16` 通常表示权重采用 4 位、激活采用 16 位；具体编码、激活 dtype 和内核路径仍需查实现。某些路径会在计算时把权重反量化到更宽的格式。
- KV cache 是否量化、偏置与归一化等操作使用什么格式，都不能从这两个简称直接推出。

在一个简化的整数点积中，若输入向量与权重向量各自共用一组参数，可将反量化后的点积写成：

```text
x_hat_i = s_x × (q_x_i - z_x)
w_hat_i = s_w × (q_w_i - z_w)

Σ_i x_hat_i × w_hat_i
  = s_x × s_w × Σ_i (q_x_i - z_x) × (q_w_i - z_w)
```

这解释了为什么内核可以先做整数运算，再处理缩放；但如果 scale 随分组变化，就不能把所有缩放因子都这样提出求和。这里也只展开了点积，没有包含偏置和输出重新量化。

典型的 INT8 点积使用更宽的整数累加，例如 INT32，之后再根据后续算子需要转换输出。累加器仍有有限范围，真实内核如何处理零点、缩放和中间结果，需要看实现，不能从权重 dtype 推断。

从 BF16 的 16 位权重变成 8 位编码，参数编码部分的理论体积减半；完整模型还要保存 scale、零点或其他元数据，运行时还包含激活、缓存和工作空间。若算子回退、反量化开销较大或瓶颈在其他环节，模型也未必明显加速。

## 8. 第一轮实践，应该验证什么？

学完上面的映射后，可以先在一个张量或线性层上做实验，再进入完整模型。验证分三个层次：

1. **检查数值映射。** 记录编码范围、scale、零点和粒度；确认零能正确表示，统计范围外输入比例、最大绝对误差与均方误差。参考值接近零时，单独使用相对误差容易误导。
2. **检查模型效果。** 在固定输入和评测流程下，与未量化基线比较任务指标。张量重构误差小，不保证任务效果最好；结果全部有限，也不代表量化可接受。
3. **检查实际收益。** 在目标硬件上固定 batch、输入输出长度等条件，测量峰值内存、延迟和吞吐，确认实际执行的内核与配置。

已有的[《LLM 低精度部署排查》]({% post_url 2026-05-31-llm-quantization-eval-sanity-check %})可以作为这一阶段的检查入口：先把 tokenizer、输入模板、解码、停止规则和评测链路对齐，才有依据把差异归因到量化。

## 小结

从数值精度走到量化，增加的是对数值集合的主动选择：用多少编码，覆盖多大范围，网格有多细，以及哪些元素共用参数。`scale` 和 `zero_point` 建立了整数与实数的对应关系；舍入与裁剪说明了这种近似会丢掉什么。

下一篇计划从具体张量分布出发，比较校准范围、离群值与量化粒度，观察为什么同样是 INT8，误差也可能差很多。再往后逐步讨论 INT4、PTQ 方法、QAT 和 FP8/FP4，并用实际部署评测判断收益。
